### 2.4 评审对草案的更正(执行按这里,不按草案)

1. **D7 的数字两端都不对**。草案写「bench 约 55×、跨 k 30–70×」。按 `bench/README.md` 现表:
   `insert` k=1/2/4/8 = 0.98 / 1.75 / 6.14 / 11.6 µs,`remove` = 54.5 / 51.6 / 58.9 / 69.4 µs
   ⇒ 比值 **≈56× / 29× / 9.6× / 6.0×,随 k 下降**。原因:两边都随 k 变贵,而 `insert` 涨得更快。
   所以只能写「k=1 约 56×,k=8 约 6×」或只给机制 + 链接,不能写「约 55×」。README/SPEC 的「20–44×」两个端点也都过时。
2. **草案 M1 的「把 `dev` 合入 `main`」不可执行**:`git merge dev` → `fatal: refusing to merge unrelated histories`,
   `--squash --allow-unrelated-histories` → 每个文件 add/add 冲突(`CONTRIBUTING.md` §Branch model 已记录三种失败)。
   正解是 `git read-tree --reset -u dev` + **一次** commit。
3. **`moon.work` 配方不要自创**。草案附录写 `[workspace]` 头;仓库**已验证**的配方没有该头
   (`.gitignore:7-15`、`cmd/leaderboard/main.mbt:19`):`members = [".", "bench", "cmd/leaderboard"]`。CI 照抄已验证配方。
4. **安装段只给 `moon.mod` 不够**。本轮实测:`moon add` 只改 `moon.mod`;若 `moon.pkg` 里没有
   `import { "aurasuisui/multiindex" }`,写 `@multiindex.` 会报 `[4020] Package "multiindex" not found`。README 必须给这一行。
5. **`moon add` 可以写死版本**:本轮在仓库外空项目实测 `moon add aurasuisui/multiindex@0.2.1` → exit 0,
   写入 `import { "aurasuisui/multiindex@0.2.1" }`。安装段直接写 `@0.2.2`。
6. **草案把「`AGENTS.md` 命令表补 all-target」列为可砍,不对**:CI 步骤一变,`AGENTS.md` 的六步描述就失真,
   Doc Sync 要求同步 —— 这是 **M3 的必做项**,不是锦上添花。
7. **发布前不要把 `cmd/`、`bench/` 升到 `@0.2.2` 后就同步 `main`**:这段时间「干净 clone + 不带 `moon.work`」
   会解析失败。因此 **`main` 同步与 tag 必须排在 `publish` 之后**,窗口只存在于 `dev`,公开面不暴露。
8. **`docs/STYLE.md:1362` 硬编码 `VERSION = "0.1.0"`**:不要改成 0.2.2(下次又漂),改成**版本无关**表述
   (例:「当前发布版本,以 `moon.mod` 为准」)。

### 3.1 M6 的唯一一次同步(不可反复)

```bash
# 前提:dev 已 publish、回填已提交、CI 绿、工作树干净
git checkout main
git read-tree --reset -u dev        # main 的树 = dev 的树,一步到位
git commit -m "chore(release): v0.2.2 —— 验收修复"
git tag -a v0.2.2 -m "v0.2.2"
git push origin main dev v0.2.2
```

> `read-tree` 会**覆盖** `main` 上的工作树 —— 执行前确认 `git status` 干净、`git log main..origin/main` 为空。
> 全程只做**一次**;之后再有提交就会重新制造 D6。

### 3.2 M3 / M4 的 grep 门禁(M4 出口用)

每条都应输出 **0**;任何一条非 0,该里程碑不算完成。

> **Windows PowerShell 5.1 陷阱(2026-10-21 实测)**:`Get-Content` / `Select-String` 默认按 **ANSI(GBK)** 读文件,
> 中文与 `⬜` / `–` / `×` 会读成乱码,连**行数**都会少算(同一份 275 行的计划,默认编码报 206)。
> 所有门禁命令**必须显式加 `-Encoding UTF8`**,否则会假绿或假红。

```powershell
Select-String -Path README.md -Pattern "^'" -Encoding UTF8                       # D1 碎片
Select-String -Path README.md,docs/SPEC.md -Pattern "20–44×" -Encoding UTF8      # D7 旧数字
Select-String -Path docs/STYLE.md -Pattern 'VERSION : String = "0.1.0"' -Encoding UTF8  # D8
Select-String -Path docs/RELEASE_CHECKLIST.md -Pattern "已升 @0.2.1" -Encoding UTF8   # D4 不实
Select-String -Path docs/plans/v0.2.0.md -Pattern "M7\.5" -Encoding UTF8              # D5 状态(人工核对状态列)
Select-String -Path cmd/leaderboard/main.mbt,bench/main.mbt -Pattern "let _ = t\.register" -Encoding UTF8  # D8
Select-String -Path AGENTS.md -Pattern "moon test$|六步" -Encoding UTF8        # M3 同步(允许 0;需人工确认措辞)
```
