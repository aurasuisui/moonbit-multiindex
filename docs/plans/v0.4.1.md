## 九、已决与已知债

**已决**

1. **D1 的哨兵要比 §12.4 更强**:`version` 抓不到 `register_*` / `unregister_index`(它们不改 version),所以同时快照 `indexes.length()`。实测:仅 `version` 会让 R1 仍然通过。
2. **D1 的严重度按 §12.3 更正**:A 路径(删别的行)只违反 abort 承诺、**不丢数据**;E 路径(删自己那行)才丢。回归测试要覆盖这两条不同的期望。
3. **D2 必须发 0.4.1**:门槛 2 要求「提交 SHA 与 tag/版本一致」,而包里那份清单写着「尚未发布」—— 是**内容**不一致,不是换行符问题。
4. **D6 删掉区间**:`26a41d7..v0.4.0` 实测 29 且 `26a41d7` 不是 tag 祖先;改成直接给「本期 N 条」+ 可复现命令。
5. **A1–A4 复杂度口径留 0.5**:本期只在 SPEC §6 加一句「以下为渐进口径,常数项见 bench/README」,不动表本身。
6. **数字必须绑定测量快照**:凡是会被后续提交改变的统计量(覆盖率、LOC、测试数、树 hash),写进文档时必须注明「测量时的 SHA」,不能笼统写「本版真值」。这条本轮踩了三次(M6c 改测试数未重跑覆盖率 / D3 误判快照 / M3 把 0.4.1 文档钉上 0.4.0 的数字)。

**已知债**(本次不做)

- OBS-1 跨表 `RowId` 无表标识:留 0.5。
- A1–A4 复杂度表按实测重写:需要连 benchmark 重跑,留 0.5。
- `0.4.0` 的 tag 与包内容不一致:**不回改**,历史版本不可覆盖。
