## 五、执行与审核规则

- **一次只派一个里程碑**;执行者(子会话)只报「待审核」,不得自行置 ✅。
- 四件必报:验证命令原样输出 / 测试计数 / commit 列表 / 做法与**偏离**。
- 审核者必须**自己复跑**验收命令,子会话自述不算证据。审核者可额外用 `plan-to-ship` 技能里的
  `plan-lint.mjs` 做本文件的结构自检——**那是审核者本地工具,不是仓库内的出口条件**。
- 每轮查两项边界:`git diff --stat` 有无碰到禁止文件;`git diff -- '*test*'` 有无放宽断言。
- **不可逆动作**(M7 的 publish / tag / main 同步)必须先拿到人类口令,一次口令只做一次尝试;
  执行前写清:要做什么 / 打哪个版本 / 失败怎么回滚 / 做完怎么验证。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 工具链在提交前又漂移,格式门禁再次变红 | 每天开工先跑 `moon version` + `moon fmt --check`;变红单独一个 style 提交修掉 |
| `rebuild_index` 原地清桶,导致在飞游标失配 | 实现必须「建新桶 → 整体替换」,不许原地 clear;配一条「重建后旧游标仍走完」的测试 |
| `rebuild_index` 在脏表上撞唯一键,把旧桶改坏 | 先全量预检唯一性,**通过后才替换**;失败时旧索引逐项不变,配专门回归测试 |
| 降序改惰性后方向或桶内顺序变化 | 用现有方向断言测试守住(只翻键序,桶内仍槽位升序);改前改后各跑一次 `moon test --target all` |
| 申报书又写成「已支持」但没测 | 承诺矩阵逐行对 mbti;没有测试的能力改写成「计划」或删掉 |
| 发布时工作树不干净,包内多出文件 | D2 的三条判据 + 从干净 clone 发布 + `moon package` 项数比对 |
| tag 与 main 不同提交 | M7 出口写死两条 `git diff --quiet` exit 0 |
| 时间不够硬做 M4 导致 M2 半成品 | 按 §六 先砍 M4,永远保住 M2 |

## 九、已决与已知债

**已决**

1. 参赛方向按用户已报名的方式推进,不包装成新项目。
2. 版本走 **0.4.0**(MINOR),不走 0.3.1。
3. 「工作树干净」是**三条判据的组合**(见 D2);并且本仓库已设 `core.autocrlf=false`(仅本机 `.git/config`,不随仓库分发),使 `git status` 重新可信。换 clone 后需重设,否则 `moon fmt` 会重新长出 10 行假阳。
4. 统计口径:生产 2498 / 测试 6069 / 生成接口 109 不计;Windows `-Filter *.mbt` 会误吞 `.mbti`,必须显式排除。
5. 本期提交从 **11/23** 起计(D6),11/22 当天不充数。
6. 只做「1 个新能力 + 1 处内部修正 + 1 个查询族」,砍掉的都是评优项。
7. 截止时间按 11/30 18:00 倒排,对外保留「以赛事官方通知为准」。
8. `rebuild_index` **不 bump `version`**:它不改记录;实现是「建新桶后整体替换」,因此在飞有序游标继续走旧快照,与 `unregister_index` 的已知行为同构。
9. `rebuild_index` 错误类型**复用 `RegisterError[K]`**,不新增公开类型;代价是 `DuplicateName` 在重建路径不可达,由 SPEC §3.1 登记(比照 §7.3 的不可达分支写法)。

**已知债**(本次不做,原因写在这里,不进代码)

- Issue #2 胖桶 `iter_by` 5.4× / 宽区间 `range_by` 21.9×:根因是 core `Iter` 逐元素装箱,自定 2× 出口条件未达。
- Issue #1 惰性 `positions`:要改核心存储的多个汇聚点与 `verify_invariants`,风险高于收益。
- `from_json` 无行数上限:维持既有行为,在 SPEC §11 登记。
- `modify` 的 Err 路径不可回滚:无 `Clone`/借用,已在 SPEC §3.7 契约化。
- `Table` 的 `Show` / `Default` / `Eq` / `Hash` / `Arbitrary`:SPEC §8 只是规划,B2 把它标成「未落地」,不在本版实现。
- 加 `.gitattributes`(如 `* text=auto eol=lf`)把 EOL 策略写进仓库、根治 D2:属于分发层面的改动,本期只用本机配置规避,不改仓库。
