## 二、项目简介

`Table[K, V]` 是一张**记录表 + N 个二级索引**:同一批记录可以按不同字段检索,索引分
**唯一 / 非唯一** × **哈希 / 有序**四个象限。记录由**稳定句柄** `RowId`(槽位 + 代际号)定位,
槽位会被复用但陈旧句柄永不复活。

定位关系一句话:**`BiMap` 是「两个互为逆的唯一索引」的特例,本库把它泛化为 N 个彼此独立的索引**,
并引入上游不具备的**记录身份**与**非唯一索引**。与 MoonBit 生态已有的
`Milky2018/slotmap`(稳定键容器,**无索引投影与按键查找**)、
`kesmeey/IndexMap` / `Hhsqoo/moon-collections`(单索引有序哈希表,**目标是保序而非多路查找**)
定位正交、不重合(对照表见 `docs/SPEC.md` §1)。

## 四、技术路线

**数据布局**:记录存于 `rows : Array[V?]`(槽位 + 空洞),配 `gens`(代际号)、`free`(空闲槽栈)、
`order`(插入序),以及索引注册表 `indexes`。**索引条目只存槽位号,值只在 `rows` 中存一份**
(单一真源);代际号只用于校验**外部传入**的句柄。

**四象限索引**(唯一性 × 有序性;与上游 `hashed/ordered × unique/non-unique` 一一对应):

| | 哈希 | 有序 |
|---|---|---|
| **唯一** | `Map[K, Int]` | `SortedMap[K, Int]` |
| **非唯一** | `Map[K, SortedSet[Int]]` | `SortedMap[K, SortedSet[Int]]` |

**一致性纪律**:所有变更汇聚到四个私有汇聚点(`insert_impl` / `remove_impl` / `modify_impl` /
`clear_impl`;`clear_impl` 是 O(n) 批量路径,避免循环删除退化到 O(n²)),
以 **9 条不变量(I1–I9)** 为靶子持续校验,并把 `verify_invariants()` **作为公开 API** 暴露,
返回 `Result[Unit, String]` —— **首个违反点带上「哪条不变量 + 哪个槽位/键」**,而不是只回一个 `false`
(可诊断性正是该 API 的全部意义)。

**正确性设计(相对参考实现的增量)**:

1. **冲突零变更**:唯一性检查全部在变更之前完成,返回 `Err` 时表与调用前等价,并把记录**原样归还**调用方。
2. **`modify` 原子性**:算新投影 → 逐唯一索引预检(排除自身)→ 全部通过后再统一落地;
   上游对应路径是「先删旧键再插新键、失败即 panic 并留下脏索引」,本库**不复现**该顺序。
3. **代际号溢出即退役槽位**,使陈旧句柄永不复活(Rust 参考实现均选择静默回绕)。
4. **绝不 panic**:可预期的运行时条件(冲突 / 陈旧句柄 / 未命中)一律 `Result` / `None` / 空迭代器;
   仅**编程错误**(索引名写错、在哈希索引上做范围查询)才 `abort` —— 二者必须分开对待。
5. **整批原子 `insert_many`**:预检**批内互相冲突**,任一条冲突即整批零变更,并以
   `DuplicateInBatch(index, key, at)` 指明批次里哪个成员先占了键(上游 `FromIterator`
   是 first-wins 的**静默胜出**规则,本库不采纳)。
6. **冲突报告顺序确定**:同一记录同时违反多条唯一索引时,报**索引名升序的第一个**
   —— 不定死则注册表是哈希表,错误会随内部顺序漂移。

**差异化能力**:范围查询(`range_by` 双闭 / `range_half_open_by` 半开 / `iter_asc_by` / `iter_desc_by`,
且惰性)是上游缺口;公开自检 API、`index_stats`、JSON 往返与整批原子写入亦为上游所无。

**质量门禁**:`moon fmt --check` → `moon check` → **`moon check --deny-warn --target all`(零警告)**
→ `moon info` + `git diff --exit-code` → `moon test` → `moon build`。

## 五、本期完成的功能、测试与文档

- **功能**:记录存储与稳定 `RowId`;四象限索引注册(`register_unique` / `register_unique_ordered` /
  `register_non_unique` / `register_non_unique_ordered`,对非空表注册即**原子回填**);
  写入 `insert` / `insert_many` / `update` / `modify` / `remove` / `clear`;
  查询 `get` / `contains` / `len` / `is_empty` / `iter`(插入序)/ `get_by` / `iter_by` /
  `range_by` / `range_half_open_by` / `iter_asc_by` / `iter_desc_by` / `has_index` / `index_names`;
  诊断 `verify_invariants` / `index_stats`;序列化 JSON 往返。
- **测试**:**78 条**用例,覆盖八个层次:

  | 层次 | 手段 |
  |---|---|
  | 不变量 | `verify_invariants`(I1–I9)在随机操作序列**每一步之后**校验 |
  | 模型对拍 | 与 `Array[V]` 线性扫描朴素实现全操作序列差分 |
  | 差分 | 对 Rust 参考实现 v0.15.1 的**黄金序列**观测对齐(夹具入库,`moon test` 不需要 Rust) |
  | 白盒 | 直读私有字段校验 `free` 一致性、代际号单调、槽位台账 |
  | 回归 | 钉死设计探针发现的 `update` 冲突漏洞与 `modify` 原子性 |
  | 压力 | >10k 操作、槽位复用风暴、单桶 1250 条的长桶 |
  | 基准 | `bench/`:与线性扫描对比 —— **点查 ~236× 快、选择性遍历 ~58× 快、窄区间 ~12× 快;胖桶遍历与宽区间则更慢**(交叉点与成因如实写在 `bench/README.md`) |

- **文档**:README(含 API 三表与实测 Gotchas)/ `docs/SPEC.md`(API 唯一真源)/ DEVPLAN /
  CONTRIBUTING / CHANGELOG / RELEASE_CHECKLIST / STYLE / MOONBIT_REF,
  文档枢纽 `docs/README.md`(含单一真源表);可运行示例 `cmd/leaderboard`。
