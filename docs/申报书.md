**项目简介**

MoonBit MultiIndex 提供一个「记录表 + 多个二级索引」的容器 `Table[K, V]`。同一批记录可以按不同字段查找，索引分为唯一与非唯一、哈希与有序四个象限。每条记录有一个稳定句柄 `RowId`，由槽位和代际号组成；槽位在记录删除后会被复用，但过期句柄不会命中复用该槽位的新记录。

MoonBit 现有的 Map 只能按一个键查找，IndexMap 这类库解决的是保留插入顺序，BiMap 解决的是两个互为逆的唯一索引。本项目把 BiMap 推广为 N 个彼此独立的索引，并补上生态里还没有的记录身份与非唯一索引。

**项目方向与通用性**

项目属于基础数据结构方向。通用性来自三点：键类型和记录类型都是泛型参数，不绑定具体业务；索引在运行时按名字注册，同一张表可以按需增删不同字段的索引；索引不参与序列化，记录与索引解耦，便于持久化和跨进程传递。凡是「同一批数据要按多个字段反复查找」的场景都可以直接复用。

**预期使用场景**

- 内存表多路检索：把用户记录放进一张表，按邮箱建唯一索引、按城市建非唯一索引、按积分建有序索引。按邮箱查是常数时间；列出某城市的全部用户；按积分区间取排行榜。不需要手工维护三张 Map 并保证它们同步。
- 配置项检索：配置项按名字建唯一索引、按分组建非唯一索引、按优先级建有序索引。启动时按名字取一项，运行时列出某分组的全部项，按优先级顺序应用。修改某项时其余索引自动保持一致。
- 仿真实体索引：仿真中存在大量实体，每个实体有稳定 ID。按阵营和类型建非唯一索引、按耐久建有序索引。实体销毁后其 ID 永不复用，此后的操作返回空，而不会误命中新建的实体。

**核心功能**

- 记录存储与稳定句柄：`Table[K, V]`，`RowId` 由槽位与代际号组成，代际号耗尽时槽位永久退役；
- 四象限索引注册：`register_unique`、`register_unique_ordered`、`register_non_unique`、`register_non_unique_ordered`，对非空表注册时自动回填；
- 写入操作：`insert`、`insert_many`、`update`、`modify`、`remove`、`clear`。唯一冲突时不改动表，并把记录原样归还调用方；
- 查询操作：`get`、`get_by`、`iter_by`、`range_by`、`range_half_open_by`、`iter_asc_by`、`iter_desc_by`、`iter`；
- 一致性诊断：`verify_invariants` 返回第一条被违反的不变量和出错位置，`index_stats` 给出索引的桶分布；
- JSON 往返：只序列化记录，反序列化后重新注册索引即可恢复；
- 质量：78 个测试覆盖单元、不变量、模型对拍、差分、白盒与压力等层次，wasm、wasm-gc、js、native 四个后端全部通过，CI 含零警告门禁。

**原创性与参考说明**

本项目为原创实现，没有移植任何代码。设计上参考了 Rust 的 multi_index_map（https://github.com/lun3x/multi_index_map，MIT 许可证），该库同样采用「记录表 + 每个索引一张查找表」的结构，索引分哈希与有序、唯一与非唯一四类。与它相比，本项目在几处做了不同选择：句柄带代际号，而对方是裸下标；索引在运行时注册，不用过程宏生成；补上了范围查询与公开的一致性自检；唯一冲突时整批拒绝并归还记录，不采用对方的 first-wins 规则。第三方来源与许可证在仓库 NOTICE 文件中逐条登记。
