# Contributing to moonbit-multiindex

## Getting Started

```bash
# Prerequisites: install MoonBit from https://www.moonbitlang.com/download/
git clone https://github.com/aurasuisui/moonbit-multiindex
cd moonbit-multiindex
moon check   # type check
moon test    # run all tests
moon fmt     # format
```

## Style Guide

| Rule | Example |
|---|---|
| Functions | `snake_case`: `get_by`, `bucket_add` |
| Types | `PascalCase`: `Table`, `RowId`, `Conflict` |
| Constants | `UPPER_CASE`: `MIN_CAPACITY` |
| Public API docs | `///|` doc comment block |
| Tests | `@aurasuisui/multiindex.` prefix for black-box access |
| Qualified trait calls | `Hash::hash(x)`, `Show::to_string(x)` |
| Length | `array.length()` (not `.size()`); effects as `raise` (not `!`) |

## Architecture Deep Dive

### Data Layout

```
Table[K, V]
├── rows    : Array[V?]                      ← slot storage; None = free slot
├── gens    : Array[Int]                     ← per-slot generation, +1 on recycle
├── free    : Array[Int]                     ← free-slot stack (LIFO)
├── order   : Array[Int]                     ← live slots in insertion order
├── indexes : Map[String, Index[K, V]]       ← hash indexes (unique / non-unique)
├── sorted  : Map[String, SortedIndex[K, V]] ← sorted indexes (range queries)
├── mut len : Int
└── mut version : Int                        ← mutation counter (fail-fast iterators)
```

**Indexes never store values** — they store slot numbers only. Values live in exactly one
place (`rows`), which is what makes "one update touches all indexes and stays consistent"
tractable. Bucket type is `Array[Int]`; removing from a bucket is a linear scan.

### The invariants (must ALWAYS hold — see docs/DEVPLAN.md §3)

```
I1  every slot in `order` is live, and appears once
I2  live record count == len == order.length()
I3  no duplicate slots inside any bucket
I4  for every bucket entry s: (idx.project)(rows[s]) == bucket key
I5  every UNIQUE index bucket has length <= 1
I6  `free` has no duplicates and is disjoint from live slots
I7  every live record appears in exactly the right bucket of every index
I8  version only increments on a real change
```

**I5 and I7 must be checked as a pair**: I7 catches "missing", I5 catches "extra". Skipping I5
is how the `update`-conflict bug (below) stayed invisible — `verify` returned true while a
unique bucket held two holders.

### Chokepoint discipline (the #1 source of bugs)

Every mutation funnels through exactly three private helpers; **no other code may touch
`rows` + `order` + `indexes` + `gens` + `free` together**:

| Helper | Steps |
|---|---|
| `insert_impl` | conflict check **before any mutation** → allocate slot → write row → bucket-add in every index → `order.push` |
| `remove_impl` | bucket-del in every index → `rows[slot]=None` → `gens[slot]+=1` → `free.push` → compact `order` |
| `update_impl` | conflict check **excluding self** → bucket-del old in every index → write row → bucket-add new in every index |

### Three high-risk paths (validated by the design probe)

1. **`update` must conflict-check *excluding itself*.** The probe showed that omitting this lets
   a record take a unique key already held by another record, silently breaking I5.
2. **Conflict checks happen before any mutation.** On `Err`, the table must be byte-for-byte
   equivalent to before the call (mirrors bimap's `insert_no_overwrite`).
3. **No observable intermediate state between old-bucket-removal and new-bucket-insertion.**
   When the key is unchanged, take a fast path instead of delete-then-add.

## Adding a Feature

1. Implement in the right `src` file (through a chokepoint if it mutates).
2. Add a `///|` doc comment.
3. Add black-box tests in `table_test.mbt`.
4. Add/extend an invariant in `property_test.mbt` (and I5/I7 if the feature touches indexes).
5. Update the API table in `README.md` **and** the contract in `docs/SPEC.md`.
6. Add a CHANGELOG entry.
7. Run the five-step CI locally.

## Doc Sync Convention(文档同步约定 · 防漂移防死文件)

单一真源(SSOT):每条事实只住一个文件,别处只链接不复制(完整 SSOT 表见 [`docs/README.md`](docs/README.md))。

| 你改了 | 必须同步更新 |
|---|---|
| 公开 API(签名/返回类型/语义) | `docs/SPEC.md` + `README.md` 的 API 表 |
| 任何行为变化 / 关键决策 | `CHANGELOG.md`(Notes / Deviations) |
| 架构 / 不变量 / 开发流程 | `CONTRIBUTING.md` |
| 命令 / 工具链 / 高层架构速览 | `CLAUDE.md` **和** `AGENTS.md`(互为镜像) |
| 新增或删除任何文档 | `docs/README.md` 枢纽的地图表 |
| bump 版本 / `moon publish` 前 | `docs/RELEASE_CHECKLIST.md` 逐项全绿,并在 `CHANGELOG.md` 记一行勾选结果 |

**收尾自检**:① 按上表联动更新;② `docs/README.md` 无孤儿条目;③ 全文 grep 不残留指向已删文件的链接;
④ 五步 CI 全绿。

## Testing Guide

| File | Type | What it tests |
|---|---|---|
| `table_test.mbt` | Unit | register / insert / get_by / remove / update matrix |
| `property_test.mbt` | Invariant | `check_invariants` (I1–I8) after every step of random op sequences |
| `model_test.mbt` | Differential | Same op stream vs a naive `Array[V]` linear-scan oracle |
| `differential_test.mbt` | Differential (Tier 1) | Op-stream observations vs the **real Rust reference**; fixture generated by `tools/diffgen`, checked in — `moon test` needs no Rust |
| `table_wbtest.mbt` | White-box | `free`/live disjointness (I6), generation monotonicity, slot inverse |
| `regression_wbtest.mbt` | White-box | Pins the `update`-conflict bug: updating into an occupied unique key must `Err` and leave the table unchanged |
| `bench_test.mbt` | Stress | 10k+ op mixes, slot-reuse storms, long buckets |
| `generics_test.mbt` | Unit | Custom struct keys, Int boundary keys, capacity stability |

Conventions:

```moonbit
test "descriptive english name" {
  let t : @aurasuisui/multiindex.Table[String, (String, String)] = @aurasuisui/multiindex.Table::new()
  t.register_unique("name", fn(p) { p.0 })
  debug_inspect(t.len(), content="0")
}
```

- Avoid `debug_inspect` inside loops with varying values (unstable `moon test -u` snapshots);
  use `@test.assert_eq` / `@test.fail` there.
- Helper functions that call `@test.assert_eq` must be declared `-> Unit raise`.
- Invariant helpers are black-box: assert through the public API, not private fields
  (private-field assertions belong in `*_wbtest.mbt`).
